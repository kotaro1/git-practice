# git-practice

Git と GitHub をゼロから学ぶための練習用リポジトリです。「名前を聞いたことがある程度」の初心者が、実際に手を動かしながら基本操作をひと通り体験した記録として作りました。同じ流れをなぞれば、他の初学者の方もGitの基本を掴めるはずです。

## このリポジトリにあるもの

| ファイル / 履歴 | 内容 |
| --- | --- |
| `memo.txt` | 練習用のテキストファイル。コミット・ブランチ・マージ・コンフリクト解決を、この1ファイルに対して繰り返し実践した |
| `.gitignore` | Gitの管理対象から特定のファイルを除外する設定例 |
| `git-github-course.docx` | この練習で学んだ内容をまとめたレッスンノート（Word形式） |
| コミット履歴 (`git log`) | 「最初のコミット」→「ブランチでの変更」→「コンフリクト」→「GitHub連携」までの一連の流れがそのまま残っている |

実際にこのリポジトリの `git log --oneline` を見てみると、学習の過程がそのまま履歴として残っているので、「Gitで何ができるか」を疑似体験する教材としても使えます。

## Git / GitHub とは

- **Git** — ファイルの変更履歴を記録し、必要ならいつでも過去に戻ったり、別の作業ルート（ブランチ）に枝分かれさせたりできる、ローカルで動く履歴管理の仕組み。
- **GitHub** — そのGitのリポジトリをインターネット上に置いて、バックアップしたり、他の人と共有・共同作業したりできるサービス。

「Git = 道具そのもの」「GitHub = その道具を使ったデータをクラウドに置くサービス」という関係です。

## 基本の考え方: 3つの場所

Gitでは、ファイルは常に次の3つの場所のどこかにいます。

```
作業ディレクトリ  →  ステージングエリア  →  リポジトリ
  (今編集中)         (次のコミットの予約リスト)   (記録が確定した場所)
```

1. **作業ディレクトリ** — 今エディタで開いて編集している普通のファイル
2. **ステージングエリア** — `git add` で「次のコミットに含めたい変更」を選ぶ場所
3. **リポジトリ** — `git commit` で確定した記録（コミット）が積み重なっていく場所

## よく使うコマンド一覧

### ローカルでの基本操作

| コマンド | 意味 |
| --- | --- |
| `git init` | 今のフォルダをリポジトリにする |
| `git status` | 今の状態（変更済み・未追跡など）を確認する |
| `git add <file>` | ファイルをステージングエリアに追加する |
| `git commit -m "message"` | ステージング済みの変更を記録として確定する |
| `git log` / `git log --oneline` | コミット履歴を見る |
| `git diff` | まだaddしていない変更内容を見る |

### ブランチ

| コマンド | 意味 |
| --- | --- |
| `git branch` | ブランチの一覧を見る |
| `git switch -c <branch>` | 新しいブランチを作って、そこに移動する |
| `git switch <branch>` | 既存のブランチに移動する |
| `git merge <branch>` | 指定したブランチの変更を、今いるブランチに取り込む |
| `git branch -d <branch>` | 使い終わったブランチを削除する |

### GitHubとの連携

| コマンド | 意味 |
| --- | --- |
| `git remote add origin <url>` | GitHub上のリポジトリと紐付ける |
| `git push -u origin <branch>` | ローカルの変更をGitHubへ送る（`-u` で以降 `git push` だけでOKになる） |
| `git pull` | GitHub側の最新の変更をローカルに取り込む |
| `git clone <url>` | GitHub上のリポジトリを丸ごと手元にコピーする |

## コンフリクト（衝突）が起きたら

2つの異なるブランチが同じ箇所を別々に変更した状態で `git merge` すると、Gitはどちらを採用すべきか判断できず、ファイルの中に次のようなマーカーが挿入されます。

```
<<<<<<< HEAD
自分の変更
=======
相手の変更
>>>>>>> ブランチ名
```

直し方はシンプルで、エディタでファイルを開き、`<<<<<<<` ・ `=======` ・ `>>>>>>>` の記号を削除して、残したい内容だけを書き換えるだけです。直したら、いつも通り `git add` → `git commit` でマージが完了します。

## よくあるトラブルの逃げ道

| 状況 | 対処 |
| --- | --- |
| ステージングから外したい | `git restore --staged <file>` |
| 直前のコミットメッセージを直したい | `git commit --amend -m "正しいメッセージ"` |
| 変更を破棄して元に戻したい（注意: 変更は消える） | `git restore <file>` |
| 今のブランチを忘れた | `git branch` |
| pushが "rejected" される | 先に `git pull` してから再度 `git push` |

## 学び方のヒント

- 何かを壊すのが怖いうちは、練習用のフォルダで `git init` して、遠慮なく壊してみるのが一番早いです。ブランチを切っておけば、失敗しても本線（`main`/`master`）は無傷です。
- コンフリクトは最初は誰でも焦りますが、中身はただのテキストファイルの編集です。一度自分で起こして直してみると、怖くなくなります。
- コマンドを覚えるより先に、「作業ディレクトリ → ステージング → リポジトリ」という3段階の流れを体で覚えると、あとから出てくるコマンドの意味が理解しやすくなります。

より詳しい解説は同梱の `git-github-course.docx` にまとめてあります。
